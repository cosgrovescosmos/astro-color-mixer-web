Astro Color Mixer Technical Appendix

Introduction

This appendix summarizes the practical processing model used by Astro Color Mixer Web for nonlinear RGB astrophotography refinement.

Nonlinear RGB assumptions

The app assumes nonlinear RGB input, normalized floating-point working values, downsampled preview interaction, and full-resolution save rendering.

Luminance formula

Y = 0.2126 R + 0.7152 G + 0.0722 B

This luminance is used for Range Mask, diagnostics, neutral luminance shaping, and protection terms.

Hue and saturation selection

Hue is treated as circular. Low saturation makes hue unreliable, which is why weak-color pixels use a separate neutral luminance path.

Color-band centers

red 0°
orange 30°
yellow 60°
green 120°
cyan 180°
blue 240°
purple 275°
magenta 315°

Width and Feather

Width defines the selected hue span and Feather defines the soft falloff into neighboring hues.

distance = circularHueDistance(hue, center)
mask = 1 - smoothstep(innerWidth, outerWidth, distance)

Range Mask formula

leftRamp = smoothstep(low - feather, low, Y)
rightRamp = 1 - smoothstep(high, high + feather, Y)
rangeMask = clamp01(leftRamp * rightRamp)

Neutral / Low-Saturation model

neutralMask = 1 - smoothstep(satStart, satFull, saturation)

This provides a luminance-focused path for low-saturation pixels where hue is unreliable.

Chroma-vector adjustment concept

Conceptually, the app separates a luminance-like component from chroma, scales saturation, rotates hue, adjusts luminance, then recombines and clamps to valid RGB.

Refinement pass sequencing

working = original
for each enabled pass:
    working = applyPass(working, pass)

Preview/downsample behavior

Preview, histogram, polar plot, and probe are tied to downsampled working data for responsiveness. Saved output renders from the full-resolution image.

TIFF/browser considerations

TIFF support depends on the included browser-side TIFF I/O code and the available memory of the local browser session. Large images can be memory-intensive.

Limitations

The app is not for linear calibration, extreme changes can artifact, hue is unreliable in neutral regions, and browser memory limits can affect very large images.
